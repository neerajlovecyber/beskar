# Beskar Shell - Agent Notes

Beskar is a macOS / iNiR-style Wayland desktop shell for **niri**, built with **pleamar**: a Rust
runtime that draws a declarative scene language (`.plm`) and runs sandboxed Luau logic (`.luau`).
There is no Rust/GPUI code to write here. Everything lives in `shell/`.

Use the `pleamar` skill when touching any `.plm` / `.luau` file.

## Layout

| File | What it is |
| :--- | :--- |
| `shell/desktop.plm` | The shell's main process (rule 57): brings `panels`, `topbar`, `notifications`, the headless owners (`system`, `weather`, `activities`, `personal`) and `settings` into ONE process (`import scene`). |
| `shell/topbar.plm` + `topbar.luau` | The frame: one full-screen surface per monitor that draws the glass (ring, three top islands, dock island) AND the content of every panel (rule 70). The panels are parts it includes (`common/cc_panel.plm`, `updates_panel.plm`, `info_panels.plm`, `timer_panel.plm`, `personal_editor.plm`, `dock_panels.plm`, `dialog_panels.plm`, `window_panels.plm`, `notice_view.plm`); their logic is loaded by `topbar.luau` through one panel client (`cc.luau`, `updates_panel.luau`, `info_panels.luau`, `dock_panels.luau`, `dialog_panels.luau`, `window_panels.luau`, `session_menu.luau`). |
| `shell/system.plm` + `system.luau` | The system services held ONCE (battery, network, audio volume / muted, brightness, and what is playing with the player controls): the other scenes read `System.bat.percent`, `System.net.online`, `System.sound.volume`, `System.display.level`, `System.is_playing`… (rule 58). |
| `shell/weather.plm` + `weather.luau` | One location, forecast request and offline cache; bar, Today, weather panel and widget snapshot read this owner (rule 62). |
| `shell/panels.plm` + `panels.luau` | The OWNER of which panel is open (`open`, `cur`, `panel_h`, `panel_mon`, `open_screen`, `fresh`): the frame and every merged panel read it and ask with typed events (`Panels.show`, `close`, `height`…). |
| `shell/notifications.plm` + `notifications.luau` / `notif.luau` | The notification server and owner of the notices, history (`~/.local/share/pleamar/notifications/`), DND and quiet rules. It has NO surface: the frame draws the centre and the banner card by reading its models by name (rule 70). |
| `shell/settings.plm` + `settings.luau` | The Settings window (rule 25). |
| `shell/wallpaper.plm` + `wallpaper.luau` | The wallpaper, its OWN process (rule 29 and 57). |
| `shell/widgets.plm` + `widgets.luau` | Desktop widgets, its own process (rule 27). |
| `shell/lock.plm` + `lock.luau` | The lock screen, its own process (rule 26). |
| `shell/capture.plm` + `capture.luau` | The capture picker, started on demand (rule 56). |
| `shell/common/` | Shared: `theme.plm` (part), `geometry.plm`, `icons.plm`, `ui.plm`, `buttons.plm`, `calendar.plm`, `scroll.plm` (libraries), the panel parts listed under topbar, `morph_core.plm`, `palette.plm`. |
| `shell/start.sh`, `supervise.sh`, `migrate.sh`, `smoke.sh`, `rig.sh`, `verify.sh` | Start / stop the processes (wallpaper, desktop, lock, widgets) under one supervisor (which runs the idempotent data migration first); `smoke.sh` opens every panel and reads the log; `rig.sh` runs the shell in a nested niri; `verify.sh` is the gate before a commit (compile, every test, UI guard, smoke in the rig). |
| `bin/exp/pleamar` | The runtime the shell needs: pleamar 0.8.0-exp.21 (pinned and built by `shell/runtime.sh` into `bin/exp/`). `bin/pleamar` is the old 0.7 and cannot run this shell. |

**Old scene names.** `controlcenter`, `infopanels`, `dockpanels`, `dialogs`, `windows` (and before them `weather.plm`, `music.plm`, `dashboard.plm`, `updates.plm`, `polkit.plm`, `welcome.plm`, `modals`, `overlays`) no longer exist: their panels are parts of the frame (table above). A rule below that names one of them means the part that now holds that panel; `--say topbar` reaches all of them.

## Tools

```
./bin/pleamar --check shell/x.plm          # compile only; run after EVERY edit
./bin/pleamar --docs reference | logic     # the language and the Luau API
./bin/pleamar --say <scene-stem> describe  # what a running scene shows (zones, texts, positions)
./bin/pleamar --say <scene-stem> "press <zone> right"
grim -o HDMI-A-1 out.png                   # screenshot a monitor
```

**Test rig and gate (use these, not the live desktop):** `shell/rig.sh start|say|key|shot|log|stop` runs this tree's desktop, wallpaper and
widgets in a nested niri with its own session D-Bus, pleamar sockets, HOME and data folder, stubbed system commands and no polkit
agent (`BESKAR_RIG=1`); `shell/verify.sh` (or `--no-rig`) compiles every process, runs every `tests/*.lua`, the UI guard and the full
smoke INSIDE the rig. Run it before every commit.

Scene sockets are named after the file stem in `$XDG_RUNTIME_DIR/pleamar/`. Logs: `/tmp/pleamar_<name>.log`.
Restart one scene by killing its PID (never `pkill -f` / `pgrep -f` from the same shell line: the
pattern matches the invoking command) and relaunching `bin/pleamar --no-hud --scene shell/x.plm`.

## Rules learned the hard way

1. **Right-click quits.** pleamar quits a scene's process on a right-click unless *some* rule in it
   uses `on press right`. Every scene with zones needs one (an empty `on press right zone { }` is enough).
2. **`screens: each` and props.** Loose `prop`/`follow`/`fact` on a per-monitor surface are shared by
   all copies, so a `follow` reading a layout's `.width` gets 0. Put the drawing, props and follows
   inside a `component` and instantiate it once. Per-monitor data comes from a `model` indexed by
   `$screen` (`mon.$screen.active`).
3. **Content-sized shapes.** Name a layout (`row left_row {…}`) and read `left_row.width`; chase it
   with a `~calm` spring. Shapes in one `body` that use `blend:` melt into each other (smooth union).
4. **Layout vs. anchor.** `center` in a layout is horizontal only; use `anchor: center middle` to centre both ways.
5. **Input.** On a full-screen surface only zones catch the mouse; everything else is click-through.
6. **Glass over bright wallpaper** needs `smoke` (dark) / `milk` (light) and a higher `tint`.
7. **Luau sandbox.** No `io` / `os`. Use `run(cmd, args, cb, opts)`, `spawn(...)`, `json.decode`, and
   declare every command and service in the scene's `permissions { run: …, services: … }` (commands by
   their first words, e.g. `"niri msg"`). Never block the logic thread.
8. **Tray.** The backend has one listener: only the logic owns it (`sys.watch("tray", fn)` → `model.icons`).
   Do not also declare `service tray` in the scene.
9. **niri.** The `workspaces` service is Hyprland-only: use `niri msg -j workspaces|windows|outputs`
   and `niri msg -j event-stream`. The 6 px ring is kept clear of windows by `struts` in
   `~/.config/niri/config.kdl`.
   Nothing user- or machine-specific is hard-coded: the user name, home, monitors, weather location and
   time zone all come from the system (`weather.luau`, `$HOME`, `niri msg`, `date`).
10. **One panel at a time.** Panels: the `Panels` owner scene has ONE `cur` / `open`, so opening a panel replaces the one shown, and `panels.luau` ends with `require("exclusive")("panels")` (`shell/exclusive.luau`, its `PANELS` list is `settings`, `panels`, `topbar`), which closes the OTHER windows (Settings, the power menu) when a panel opens. Settings and the power menu do the same with their own `require("exclusive")(...)`. A scene that says to another needs `say:<scene>` in its `permissions`.
11. **Colours come from `shell/common/theme.plm`; the LOOK is owned by Settings.** The facts (`dark_mode`, `skin`, `accent`, `accent_auto`, `hour12`, `pal_*`) belong to the `settings` scene (controls, saved file `~/.config/pleamar_shell.json`, palette engine). A scene in `desktop` says `uses scene "settings.plm" as Settings` before `scene` and includes `common/theme_owner.plm` (lets reading `Settings.<name>`) then `common/theme.plm` (the colour tokens: `accent_c`, `ok_c`, `danger_c`, `focus_c`, `ink_c`, `ink_sub`, `card_fill`, `item_solid`, `bg_color`, … use them instead of hex values); its Luau reads `fact["Settings.hour12"]`. A scene that is its OWN process (lock, widgets, capture) includes `common/theme_facts.plm` instead (its own facts), and Settings tells it by `say` (`THEMED` in settings.luau; `start.sh` restores the look at login the same way). To change the look, ask Settings (`say settings "emit set_dark_mode 1|0"`, `"emit choose_skin N"`): never write the facts from another scene.
12. **Which screen is which monitor.** With `screens: each` the compositor decides which copy is on which output, and it changes between runs. Never assume `screen.index` follows sorted output names: `topbar.luau` reads pleamar's startup log (`surface N on NAME`) to learn it and builds every per-monitor model (`mon`, `ws_list`) from that.
13. **Panels: the frame draws the glass AND the content (see rule 70 for how).** `Panels` owns which panel is open; a panel opens ONLY through the frame (it picks the monitor): `--say topbar "emit open_panel N"` (numbers in `FOCUS_PANELS`) or `open_island_panel(name)`. The frame grows the island's glass from facts (`cp_*`, `rp_*`, `bp_*`: on / screen / w / h) through springs, and in the SAME `Shell` component places the panel's `…Content()` component over it: `show: Panels.cur == N and <island spring> > 0.01 and <island>_screen == screen.index`, `move:` to the panel's origin (top islands: just under the bar; dock panels: `screen.height - Panels.panel_h`), opacity from the spring and the glass having arrived, and a `clip box` following the glass. A panel's logic is `module("name", function(panel, opened, shown, closed) … end)` through the frame's one panel client (`panel.height(h)`, `panel.width(w)`, `panel.keep()`). Key rules are guarded with `Panels.cur == N` (`open` / `cur` / `fresh` in the frame mean the POWER MENU's, so always write `Panels.open`, `Panels.cur`, `Panels.fresh`). `cur` ids: 1 Control Center, 2 notifications, 3 today, 4 spotlight, 5 wallpapers, 6 clipboard, 9 music, 10 widget bar, 11 session dialog, 12 polkit dialog, 15 weather, 16 updates, 21 app switcher, 22 window overview, 24 welcome, 25 personal, 26 timer. A new panel: metadata in `panels_data.luau`, a part with its facts and a `…Content()` component included by `topbar.plm`, a placement group in `Shell`, its id in the panel client in `topbar.luau`, its `.luau` returning `function(module)` or the module body, a field (if any) declared loose after `Shell()`, its id in the frame surface's `keyboard:` condition if it takes keys, and `shell/smoke.sh` + `shell/verify.sh`. A scene NEVER writes another scene's fact; owners declare events (`Notifications.set_dnd`, `Settings.set_tab`, `Panels.set_screen`…).
34. **(Historical) `PanelBody` / `common/panelbody.plm`** was the wrapper of the old separate panel surfaces. No panel uses it any more; the frame's placement group (rule 13) does its job: content laid out at its FINAL place, never moved while the glass grows, revealed by the clip, faded in once the glass has arrived (`fit` within ~24 px). Content that must sit at the bottom of a dock panel uses `Panels.panel_h`, not the animated height.
37. **Click outside closes a panel.** The frame's full-screen `outside_zone`, declared before every button zone, is active while a panel owns an island (`rp_on`, `cp_on` with `cp_kind == 0`, `bp_on` unless `bp_keep`). A press emits `outside_click`; `topbar.luau` sends `Panels.outside_close`, which closes the open panel except `panel.keep()` ones (welcome, widget bar, polkit). The panel content is drawn in the same surface AFTER this zone, so its own zones are on top of it.
16. **Volume / brightness / microphone feedback is a card in the centre pill, like a notification banner** (`kind = 2`, `osd_kind` 0 volume · 1 brightness · 2 microphone mute, `cp_w` 380 / `cp_h` 58 so the pill grows downward; owner id 8 in `topbar.luau`; the old floating `osd` scene is gone): `sys.watch` on `audio` and `brightness` shows it for any change, whoever made it; keys go through `start.sh vol-up|vol-down|mute|bright-up|bright-down` → `emit osd_*`. A dashboard open keeps it away; it takes the island from a banner.
17. **A notification appears INSIDE the centre pill.** The banner is a `kind = 1` panel (id 7) of the centre island in `topbar.luau`'s arbiter: the frame grows the island and fades the clock (`cp_kind`, `bnv`); `notifications.plm`'s `banner` surface (negative top margin so it starts above the bar's strip) draws only the card; `notifications.luau` shows it for a few seconds on a fresh notification, keeps it while hovered, opens the centre on a click, and stays away when Do Not Disturb is on, the centre is open or a real panel (the dashboard) owns the island. Other transient things (volume / brightness, music, recording) should use the same pattern.
19. **Music lives in the centre pill.** the `System` scene watches `media` (rule 58) and `topbar.luau` reads it: while a player has a title, the clock pill gets a circular cover and three `wave` bars (flat when paused); a click opens `music.plm`, a morph panel (id 9, island `cp`) with cover, title, seekable progress and prev / play / next, driven by `music.luau` (`media.*` calls, position carried on every second). Declare every event the logic receives with `->` in `topbar.plm`, or it never arrives.
20. **The centre can group by app (off by default; Settings → Notifications → Group by app, fact `group_apps`).** `notifications.luau` builds `model rows` (kind 0 card, 1 stack, 2 header of an open group; `h` is each row's height, `live_h` their sum): an app with several waiting shows one stack (the newest, two edges behind it, `+N`), a click opens it, "Show less" closes it, × dismisses the whole app. The banner still reads `notices`.
21. **Capture and recording** (`capture.luau`) only use `run` / `spawn` (no `os.execute`; `spawn` needs an `on_line` function, not nil). While `wf-recorder` runs, the clock pill shows a red dot and the time (`rec_on` / `rec_time` facts in `topbar.plm`, set through `say`); a click there sends `emit toggle_record` to the capture scene.
22. **App switcher and session dialog** are panels that grow out of the dock (rule 13; they used to be centred windows). App switcher: `Super+Tab` (niri bind → `start.sh appswitcher`), windows from `niri msg -j windows` sorted by `focus_timestamp`, icons from the apps service; Tab / arrows / Enter / Esc. Session dialog: opened by the Apple/power menu (`Log Out…`, `Restart…`, `Shut Down…`, 60 s countdown). Scenes started by `start.sh` use absolute `--scene` paths: when restarting one by hand, match `shell/<name>.plm` (not `scene shell/…`) or you leave a duplicate running.
23. **Spotlight is more than an app list** (`spotlight.luau`): every row is an entry `{ name, sub, kind, icon, run }` (kind 0 app, 1 calculator result, 2 web search, 3 command). Sums are evaluated by a small parser (no `loadstring`), `g|ddg|yt|gh|w|maps <text>` search the web through `xdg-open`, `> text` (or a command's name) lists commands, and with no match it offers a web search. Command descriptions and routes live in `shell/actions.luau`, shared with Settings; panel IDs and frame routes live in `shell/panels_data.luau`. Matching and bounded launch history are in `shell/spotlight_search.luau` (checks: `lua tests/spotlight.lua`). `/` searches files/folders through `shell/spotlight_files.luau` (300 ms debounce, one bounded `timeout … fd` process, NUL-delimited paths, optional scene-local `spotlight-files.json` roots); `@` searches open windows, `?` searches Settings pages; ordinary searches include both alongside apps. App launch ranking is saved through the dock panel scene's files service (`spotlight-history.json`), with no window titles or query history. Commands still execute under the caller's declared permissions.
24. **The clock** shows only the time in the centre pill (no date): `clock_text`, painted by `topbar.luau` (and the same in `dashboard`, `lock`) through `shell/clockfmt.luau`. `hour12` (default true: `2:05 PM`; false: `14:05`) is a theme fact: Settings → General → "24-hour clock" flips it, broadcasts it with the theme and saves it in `~/.config/pleamar_shell.json`; `start.sh` restores it.
25. **Settings** (icon glyphs are nudged by `GLYPH_DX` in `settings.luau`: nerd-font glyphs are not symmetric in their box, so measure and offset) (`settings.plm` + `settings.luau`) is a sidebar (with search; `model cats`) and 8 tabs (Wi-Fi, Bluetooth and wallpaper choice live in the Control Center and the wallpaper picker, not here), all backed by real controls: Appearance (light / dark / auto by time of day: `appearance` fact, `set_mode`; the Control Center's tile sends `set_dark_mode`), Displays (niri `msg output` scale / mode), Sound (audio service), Notifications (`banners`, `banner_ms`, DND → notifications scene), Menu Bar & Dock (`pref_*` facts in topbar), Shortcuts (parsed from niri's `binds` blocks; `Super + /` opens it), General, Software Update (`checkupdates`). Preferences are saved in `~/.config/beskar/prefs.json` (look and clock in `~/.config/pleamar_shell.json`). Settings OWNS them: the bar's (`pref_seconds`, `pref_weather`, `pref_tray`, `pref_dock_auto`, `bar_style`) are read by the frame as `let pref_x = Settings.pref_x` and `fact["Settings.pref_x"]`, the notifications' `banners` and `group_apps` the same; only what is not read by name is pushed by `say` (widgets' `widgets_on`, `banner_ms`, `dnd`: `push_prefs`). Never test a preference with `bar_style_pick` and friends on the live shell without putting the value back: they SAVE. Components (`Card`, `ToggleRow`, `SliderRow`, `Seg`, `Chip`, `Btn`, …) keep every tab short: use them for a new option.
26. **The lock screen** (`lock.plm` / `lock.luau`) is `kind: lock` (ext-session-lock): blurred wallpaper, big clock and date, your picture, a password pill (PAM through `auth.check`), a shake and a message on a wrong password, and Sleep / Restart / Shut Down (the last two need a second tap). It has NO bypass. A lock surface's `size` is a box centred on each monitor (paint the backdrop far beyond it) and `screen.width` / `screen.height` are not usable in it; every event the logic receives needs `->` (the old lock never unlocked because `unlock` lacked it). Never test a lock against the live session: run a nested niri (`env -u NIRI_SOCKET niri -c min.kdl`, it prints `wayland-N`) and start the scene with `WAYLAND_DISPLAY=wayland-N`, screenshot it with `WAYLAND_DISPLAY=wayland-N grim`. Recovery if the locker dies: from a text console, `XDG_RUNTIME_DIR=/run/user/$UID WAYLAND_DISPLAY=wayland-1 bin/pleamar --say lock "fact locked false"`. Lock when away: `shell/idle.sh <minutes>` writes `~/.config/beskar/hypridle.conf` (idle and before sleep) and runs hypridle; Settings → General sets it (off by default).
27. **Desktop widgets** (`widgets.plm` + `widgets.luau`, plan in `docs/WIDGETS_PLAN.md`): ONE scene, one `level: bottom` surface per monitor (`level: bottom, top while editing`; NOT background: the wallpaper scene is a background surface too and the one created last is on top, so after any wallpaper restart the widgets vanished behind it), click-through except the cards. `model ws` (id, scr, kind, sz, x, y) is the desktop; a `Card(w)` component per record draws the glass plate and one face chosen by `w.kind` (1 clock, 2 date, 3 weather, 4 battery, 5 system, 6 music, 7 month calendar, 8 day progress, 9 volume + brightness sliders; size 0 small 160x160, 1 medium 336x160, 2 large 336x336). There is NO slot pool: a card exists only while its record does (the model is `max 16`: every `max` copy is compiled in, so keep it small). `widgets.luau` is the only writer of `~/.config/beskar/widgets.json` (cards per output NAME, atomic write, debounced) and learns which copy is on which output from `/tmp/pleamar_widgets.log` (start.sh must log there). Feeds (weather, system) start only while a card of that kind exists. The toolbar of edit mode is its own scene, `widget_bar.plm/.luau` (panel id 10, island `bp`, `open_panel 7`): it grows out of the dock like Spotlight and the wallpaper strip, its buttons only `say widgets "emit …"`, and the bar opening / closing and edit mode start and end together (`w_bar_open`, `edit_done`); kinds and presets live in `widgets_data.luau`, shared by both scenes. Edit mode (`edit_toggle`: Apple menu "Edit Widgets…", Spotlight `Edit Widgets`, `Super+Shift+W` → `start.sh widgets`, Settings → Menu Bar & Dock): dim, drag (`drag_id/dx/dy` facts; with Grid on a card lands on the nearest free cell of the card grid: cells of 160 px with a 16 px gap, origin 48,72, so the gap is always 16; Tidy up packs everything in reading order; toggling Grid only changes how the next drops land, it never moves cards), size button cycles the allowed sizes, ✕ removes, Undo (20 snapshots), add chips and layout presets (in the bar) (Glance, Dashboard, Focus, Listening, Bare). Settings can hide all widgets (`pref_widgets` → `widgets_on`). To add a widget kind: a face component + `group { show: w.kind == N; … }` in `Card`, an entry in `KINDS` (widgets.luau) and its data. Test in a nested niri (rule 26) and mind that `--say widgets-<pid>` must be run with the nested `WAYLAND_DISPLAY`.
28. **The colour engine** (settings.luau, theme.plm): "Colours from the wallpaper" (`accent_auto`) picks the picture's dominant colour with ImageMagick (12 colours, scored by coverage, a little by saturation, ignoring near black or white; matugen's own `--prefer saturation` chose yellow specks on a grey wallpaper) and runs `matugen color hex <that> --json hex --dry-run -m dark -t <scheme>` (style Tonal / Vibrant / Neutral / Soft = `pal_style` 0-3; Soft is Tonal at tones 70 / 60 with 22 % of the colour removed: matugen itself has only the schemes and `--contrast`, no chroma setting), keeps accent (primary tone 60 dark / 50 light), a second colour (tertiary) and the surface, for both modes, in `~/.config/beskar/palette.json`, and sends the ones for the current mode as `pal_*` facts (0..1) to every themed scene (`push_palette`, also after every theme broadcast and again 3 s and 8 s after start). `theme.plm` turns them into `accent_c`, `focus_c` and `bg_color` through `pal_on` (`rgb(...)`); the frame's and widgets' `bar_color` use `surf_c`. The wallpaper picker only sends `text pal_src <path>` to settings. Any new colour that must follow the wallpaper has to use the theme tokens, never a hex value.
29. **The wallpaper is painted by pleamar, not awww** (`wallpaper.plm` + `wallpaper.luau`, started first by `start.sh`, which also stops any leftover `awww-daemon`): one `level: background` surface per monitor with `reserve: -1` (without it the compositor puts the surface below the bar's reserved strip and the top shows grey) draws `~/.config/beskar/wallpaper` with `fit: cover`; the picker (wallpapers.luau) writes that file and says `text wp_new <path>` to the `wallpaper` scene, which loads the new picture as `wp_b` and reveals it over `wp_a` (`wp_fx` 0 circle growing from the top right, 1 fade, 2 wipe), then swaps. If the shell is not running there is no wallpaper (the price of having no daemon). Nothing else in the repo may call `awww`.
30. **Other apps wear the theme** (`shell/appthemes.sh`, `assets/matugen/`): Settings → Appearance → "Theme other apps" (`pref_apps`, on by default, saved in prefs.json). On every theme change (`apply_apps` in settings.luau, debounced, plus 5 s after start) it runs `appthemes.sh setup` (idempotent: one include line per app, each file saved once as `<name>.beskar-bak`; every line contains `beskar/themes` so `remove` can take them out, and NO inline comments: kitty reads them as part of the path) and `appthemes.sh apply dark|light <source #hex> <scheme>`, which renders our own matugen templates (`assets/matugen/config.toml` + `templates/`, matugen `{{colors.<role>.default.hex}}` syntax) into `~/.config/beskar/themes/`: kitty, alacritty, ghostty, foot, `gtk.css` (libadwaita named colours, imported LAST from `~/.config/gtk-3.0|4.0/gtk.css`), and a qt5ct/qt6ct colour scheme; it also sets gsettings `color-scheme` and the adw-gtk3 theme, and reloads kitty (USR1; alacritty live-reloads). The source colour is the wallpaper palette's (`PAL.src`) or the chosen accent. ANSI colours are fixed readable sets with the accent as blue (`@A<n>@` placeholders). Qt apps need `QT_QPA_PLATFORMTHEME=qt6ct` in niri's `environment` (next login). Test with a fake `$HOME` and nested niri, never by hand-editing the user's terminal configs.
31. **Polkit agent** (`polkit.plm` + `polkit.luau`, started by `start.sh`, panel number 8 in `FOCUS_PANELS`): the logic's `sys.watch("polkit")` makes this process the session's authentication agent (one per session: never start a second one, a nested test shell included while the live one runs; test nested BEFORE starting it live, or with `pkexec true`). A modal sheet like the session dialog (`open_screen`, keyboard exclusive): polkit's message, the prompt, a password field (`secret` must be a literal, so it is always hidden), Enter / Authenticate answers (`polkit.answer`), Esc / Cancel gives up (`polkit.cancel`: the program is told "Request dismissed"), `error == "wrong"` shows "Wrong password, try again" and shakes. Every wrong answer counts for pam_faillock like any login: `faillock --user $USER --reset` after tests.
32. **Install, doctor, update, welcome**: `./beskar` (repo root) is the user-facing command: `doctor` (read-only checks with the Arch package line), `install` (clones and builds pleamar if missing, writes `~/.config/niri/beskar.kdl` with spawn-at-startup, struts, the Qt env and the binds, and one `include "beskar.kdl"` line in config.kdl with a `.beskar-bak` backup; it leaves a niri config that already mentions `start.sh` alone), `update` (git pull --ff-only for Beskar and pleamar, rebuild, restart), everything else goes to `shell/start.sh`. First run: `welcome.plm/.luau` (panel number 9) opens itself 7 s after the shell starts when `~/.config/beskar/welcome-done` is missing: three pages (what it is, light / dark / auto + wallpaper colours + theme other apps through `say settings`, shortcuts); `./beskar welcome` shows it again. Test `install` with a throwaway `HOME` containing a valid multi-line KDL config, never against the real one.
33. **Night light, power mode, privacy dots**: Settings tab 8 "Night Light & Power". Night light is `shell/nightlight.sh off|on K|auto K` (wlsunset: niri supports wlr-gamma-control; "on" is a constant K through `-t K -T K+1 -S 23:59 -s 00:00`, "auto" uses `~/.config/beskar/location` for sunrise/sunset, else 06:30 to 18:30); the choice is `night` / `night_t` in prefs.json and `start.sh` restores it at login. Power mode is `powerprofilesctl get|set power-saver|balanced|performance` (power-profiles-daemon; the card says so when it is missing). 47. **Never start the shell from an agent / terminal session directly.** Anything a tool call starts (even with `setsid`) lives in that session's cgroup (`t3code-claude-*.scope`) and is SIGKILLed when T3 ends or restarts the session: that is why the whole shell "stopped randomly" (no pleamar process, no supervisor). ## Working style

- Reuse before writing: the reference repos in `references/` (inir, minflair, capsule, pleamar, …) show
  island geometry, morphing and tray handling worth adapting, but port the *idea* into `.plm`, not their code.
- Verify visually: restart the scene, `grim` both monitors, look at the result. `--check` passing does not mean it looks right.
- Do not commit unless asked.

Exp.8 scopes scene colour lets; implicit lookups from shared controls inside `PanelBody` children fail. Keep the library imported once; including it per scene duplicates component declarations.

60. **Closed-panel ghosts on niri/AMD.** Settings and panels retire normally after their fade. On this session, pleamar's own partial-damage buffers retained faded notification, Today and music content even with `Panels.open=false` and `seen=0`, on both exp.8 and exp.15. `supervise.sh` now sets `PLEAMAR_SWAPCHAIN=1` for the shared `desktop.plm` process by default; its driver-managed buffers clear correctly. Keep this in startup so it survives login/restart. Other supervised processes keep their default path. `BESKAR_DESKTOP_SWAPCHAIN=0` opts out for diagnostics after an upstream fix. Do not keep closed panels permanently mapped to mask this issue. Details and close-cycle verification: `docs/RENDERING_NOTES.md`.

74. **Every key / blur rule in the frame is guarded by the monitor: `… and Panels.open_screen == screen.index`.** The frame is `screens: each`, which pleamar compiles as up to FOUR copies (one per possible monitor), and each copy runs its own rules, even copies with no monitor. 75. **Keyboard conventions for panels** (every panel follows them; see each part for its keys). Up/Down (and Tab / Shift+Tab) move a visible focus ring (`focus_c`, 2 px) through items, Left/Right through strips, sliders (5 % steps) and pages, Home/End and PageUp/PageDown where a list scrolls, Enter / Space activate, Esc goes back a level first and then closes. Focus starts fresh each time a panel opens. Found while doing it: (a) **Enter / Space act on key RELEASE, and only if the press was seen while the panel was up** (or a release within ~350 ms of opening is ignored): otherwise the Enter that opened a panel from Spotlight also fired the item under the ring; (b) **a focused text field swallows** Home, End, Delete, Enter and modifier arrows, so panels with a search field use Ctrl+Up / Ctrl+Down for first / last and `on submit` for Enter; (c) the frame's logic cannot emit even its own UNQUALIFIED events to itself: use `require("topbar_hooks").call(name, v)` and register the handler in `topbar_hooks.handlers`; (d) a fact changed by Luau does not come back through `on("fact:…")` in the same plugin. The rig's nested niri config must be multi-line KDL (`{ a; }` on one line is rejected and niri falls back to defaults with its hotkey overlay over every screenshot).


76. **The keyboard belongs to the `Keys` scene (`keys.plm` + `keys.luau`), not the frame.** pleamar delivers keys and typing only to the FIRST copy of a `screens: each` surface, so the frame (one copy per monitor) never got a key on the second monitor. `Keys` has ONE surface that follows the open panel's monitor (`screens: Panels.panel_mon`, like the Settings sheet), takes the keyboard while a panel is open, and is click-through except its fields. It (a) forwards every key the panels use to the frame as an event (`on key Down` -> `Topbar.k_down`, `on keyup Return` -> `Topbar.ku_return`, focus loss -> `Topbar.k_blur`); the frame's rules are `on k_down while Panels.cur == N and screen.index == 0` (so they run once: this replaces rule 74's monitor guard); (b) owns the panels' text fields (`query`, `clip_q`, `wb_name`, `password`, `wq`, `pe_draft`, `pe_new_task`, `tm_duration`, `wifi_pw`), drawn at the places the frame draws the panels; a field's Enter is `Topbar.sub_<field>`; (c) focuses the field the frame asks for: `fld_req = N; fld_seq = fld_seq + 1` in a rule, `require("topbar_hooks").focus("name")` in Luau. The frame's panel logic reads and writes the fields through `local text = require("keys_text")` (reads `Keys.<field>`, writes with `Keys.set_text`) and watches `on("text:Keys.<field>")`. A new key in a panel: add its `on key` forwarder in `keys.plm` and the `event k_… ->` in `topbar.plm`. `keys.plm` is imported AFTER `topbar.plm` in `desktop.plm`. **Never add a second surface to the Topbar scene** to get around this: pleamar then moves the frame's surface 0 and drops the frame copy on the second monitor. **The live shell runs from this working tree and hot-reloads every edited `.plm` / `.luau`**: do structural work in a `git worktree`, and remember that the rig has ONE output, so multi-monitor behaviour must be checked on real monitors.
