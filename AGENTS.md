# Beskar Shell - Agent Notes

Beskar is a macOS / iNiR-style Wayland desktop shell for **niri**, built with **pleamar**: a Rust
runtime that draws a declarative scene language (`.plm`) and runs sandboxed Luau logic (`.luau`).
There is no Rust/GPUI code to write here. Everything lives in `shell/`.

Use the `pleamar` skill when touching any `.plm` / `.luau` file.

## Layout

| File | What it is |
| :--- | :--- |
| `shell/topbar.plm` + `topbar.luau` | The frame: one full-screen glass silhouette (ring round all four edges, three top islands, bottom dock island). Scene name `MacTopBar`. |
| `shell/widgets.plm` + `widgets.luau` | Desktop widgets (see rule 27). |
| `shell/wallpaper.plm` + `wallpaper.luau` | The wallpaper itself (rule 29). |
| `shell/{control_center,notifications,panels,dialogs,dock,modals,settings,lock}.plm` (`panels` = weather, music, today and updates, rule 50; `dialogs` = the welcome, rule 51; `dock` = spotlight, clipboard, wallpapers, widget bar, session and polkit dialogs, rule 52; `modals` = app switcher, overview, capture, rule 53) | One scene per panel, each with its own `.luau` where it needs logic. |
| `shell/common/palette.plm` | Shared colour library. |
| `shell/start.sh` | Starts / stops every scene (one pleamar process each). |
| `bin/pleamar` | The runtime. |

## Tools

```
./bin/pleamar --check shell/x.plm          # compile only; run after EVERY edit
./bin/pleamar --docs reference | logic     # the language and the Luau API
./bin/pleamar --say <scene-stem> describe  # what a running scene shows (zones, texts, positions)
./bin/pleamar --say <scene-stem> "press <zone> right"
grim -o HDMI-A-1 out.png                   # screenshot a monitor
```

Scene sockets are named after the file stem in `$XDG_RUNTIME_DIR/pleamar/`. Logs: `/tmp/pleamar_<name>.log`.
Restart one scene by killing its PID (never `pkill -f` / `pgrep -f` from the same shell line: the
pattern matches the invoking command) and relaunching `bin/pleamar --no-hud --scene shell/x.plm`.

## Rules learned the hard way

1. **Right-click quits.** pleamar quits a scene's process on a right-click unless *some* rule in it
   uses `on press right`. Every scene with zones needs one (an empty `on press right zone { }` is enough).
2. **`screens: each` and props.** Loose `prop`/`follow`/`fact` on a per-monitor surface are shared by
   all copies, so a `follow` reading a layout's `.width` gets 0. Put the drawing, props and follows
   inside a `component` and instantiate it once. Per-monitor data comes from a `model` indexed by
   `$screen` (`mon.$screen.active`).
3. **Content-sized shapes.** Name a layout (`row left_row {…}`) and read `left_row.width`; chase it
   with a `~calm` spring. Shapes in one `body` that use `blend:` melt into each other (smooth union).
4. **Layout vs. anchor.** `center` in a layout is horizontal only; use `anchor: center middle` to centre both ways.
5. **Input.** On a full-screen surface only zones catch the mouse; everything else is click-through.
6. **Glass over bright wallpaper** needs `smoke` (dark) / `milk` (light) and a higher `tint`.
7. **Luau sandbox.** No `io` / `os`. Use `run(cmd, args, cb, opts)`, `spawn(...)`, `json.decode`, and
   declare every command and service in the scene's `permissions { run: …, services: … }` (commands by
   their first words, e.g. `"niri msg"`). Never block the logic thread.
8. **Tray.** The backend has one listener: only the logic owns it (`sys.watch("tray", fn)` → `model.icons`).
   Do not also declare `service tray` in the scene.
9. **niri.** The `workspaces` service is Hyprland-only: use `niri msg -j workspaces|windows|outputs`
   and `niri msg -j event-stream`. The 6 px ring is kept clear of windows by `struts` in
   `~/.config/niri/config.kdl`.
   Nothing user- or machine-specific is hard-coded: the user name, home, monitors, weather location and
   time zone all come from the system (`location.luau`, `$HOME`, `niri msg`, `date`).
10. **One panel at a time.** A panel's logic ends with `require("exclusive")("<scene>")` (`shell/exclusive.luau`), which closes the other panels when it opens. A new panel must be added to `PANELS` there and get `say:<scene>` permissions both ways.
11. **Colours come from `shell/common/theme.plm`.** It is a `part`: put `include "common/theme.plm"` as the first line of a scene and use its tokens (`accent_c`, `ok_c`, `danger_c`, `focus_c`, `ink_c`, `ink_sub`, `card_fill`, `item_solid`, `bg_color`, …) instead of hex values. It declares the `dark_mode`, `skin` and `accent` facts; Settings broadcasts them to every scene and saves them to `~/.config/pleamar_shell.json`.
12. **Which screen is which monitor.** With `screens: each` the compositor decides which copy is on which output, and it changes between runs. Never assume `screen.index` follows sorted output names: `topbar.luau` reads pleamar's startup log (`surface N on NAME`) to learn it and builds every per-monitor model (`mon`, `ws_list`) from that.
13. **Panels that grow out of an island: one reusable mechanism.** The frame (`topbar.plm`) draws all their glass: one shape per island (`power_m` left, `center_m`, `right_m`) driven by facts (`cp_*`, `rp_*`: on / screen / w / h) through springs, so each island stretches down into its panel as one piece of glass. A panel scene draws ONLY content: it is `screens: each`, includes `common/morph.plm` (declares `open`, `open_screen`, `panel_h`, the fade, the dismiss zone; the scene sets `mp_sw`/`mp_sh` first and wraps its content in `group { show: mp_here; move: X, -2; opacity: mp_fade }`) and its logic does `local panel = require("panel")("<name>")` then `panel.height(h)`. `panel.luau` reports open/close/height to `topbar.luau`, which arbitrates islands shared by two panels (Control Center and notifications share the right one). To add a panel: give it an id in `PANELS` (topbar.luau) and `IDS` (panel.luau), emit an event from its button that calls `open_island_panel(name)`, add it to `exclusive.luau`. Always open panels through the frame: it picks the monitor.
14. **The bottom island too.** Spotlight and the wallpaper strip grow out of the DOCK island (`bp_*` facts, `bv`/`bpw`/`bph` springs and the `dock_island` shape in `topbar.plm`: it grows up, the dock icons fade, a dock hidden by auto-hide is forced up while one is open). They are `screens: each`, anchored `bottom`, include `common/morph.plm`, and place their content with `move: X, <surface height> - ph` so it stays attached to the bottom.
15. **Separate panels open on ONE monitor, with a keyboard.** A non-`each` surface appears on every monitor, and a `keyboard: … while` condition cannot tell the copies apart (the panel then never got keys). So a panel that is its own window (Spotlight, clipboard, wallpapers, Settings, session dialog, app switcher) uses ONE NAMED surface with `screens: each` and a per-copy `open:` (`open: (open or seen > 0.02) and open_screen == screen.index`), `keyboard: exclusive while open`, and carries its dismiss zone and main group (and the dismiss rules) INSIDE the surface block. A closed copy is not mapped, so only the target monitor takes the keyboard. Do NOT use `screen.index` (or a `let` built on it) inside such a surface's content: it reads 0 there; the `open:` expression is the only place it works. Never toggle these panels directly: send `--say topbar "emit open_panel N"` (numbers in `topbar.luau`'s `FOCUS_PANELS`), which sets `open_screen` to the monitor with the focus and toggles. Test keys for real with `wtype -k Right` (a `--say … emit` bypasses the keyboard). Not done yet this way: osd, capture, lock.
16. **Volume / brightness / microphone feedback is a card in the centre pill, like a notification banner** (`kind = 2`, `osd_kind` 0 volume · 1 brightness · 2 microphone mute, `cp_w` 380 / `cp_h` 58 so the pill grows downward; owner id 8 in `topbar.luau`; the old floating `osd` scene is gone): `sys.watch` on `audio` and `brightness` shows it for any change, whoever made it; keys go through `start.sh vol-up|vol-down|mute|bright-up|bright-down` → `emit osd_*`. A dashboard open keeps it away; it takes the island from a banner.
17. **A notification appears INSIDE the centre pill.** The banner is a `kind = 1` panel (id 7) of the centre island in `topbar.luau`'s arbiter: the frame grows the island and fades the clock (`cp_kind`, `bnv`); `notifications.plm`'s `banner` surface (negative top margin so it starts above the bar's strip) draws only the card; `notifications.luau` shows it for a few seconds on a fresh notification, keeps it while hovered, opens the centre on a click, and stays away when Do Not Disturb is on, the centre is open or a real panel (the dashboard) owns the island. Other transient things (volume / brightness, music, recording) should use the same pattern.
19. **Music lives in the centre pill.** `topbar.luau` watches `media`: while a player has a title, the clock pill gets a circular cover and three `wave` bars (flat when paused); a click opens `music.plm`, a morph panel (id 9, island `cp`) with cover, title, seekable progress and prev / play / next, driven by `music.luau` (`media.*` calls, position carried on every second). Declare every event the logic receives with `->` in `topbar.plm`, or it never arrives.
20. **The centre can group by app (off by default; Settings → Notifications → Group by app, fact `group_apps`).** `notifications.luau` builds `model rows` (kind 0 card, 1 stack, 2 header of an open group; `h` is each row's height, `live_h` their sum): an app with several waiting shows one stack (the newest, two edges behind it, `+N`), a click opens it, "Show less" closes it, × dismisses the whole app. The banner still reads `notices`.
21. **Capture and recording** (`capture.luau`) only use `run` / `spawn` (no `os.execute`; `spawn` needs an `on_line` function, not nil). While `wf-recorder` runs, the clock pill shows a red dot and the time (`rec_on` / `rec_time` facts in `topbar.plm`, set through `say`); a click there sends `emit toggle_record` to the capture scene.
22. **App switcher and session dialog** are modal HUDs and stay centred floating windows on purpose (macOS does the same). App switcher: `Super+Tab` (niri bind → `start.sh appswitcher`), windows from `niri msg -j windows` sorted by `focus_timestamp`, icons from the apps service; Tab / arrows / Enter / Esc. Session dialog: opened by the Apple/power menu (`Log Out…`, `Restart…`, `Shut Down…`, 60 s countdown). Scenes started by `start.sh` use absolute `--scene` paths: when restarting one by hand, match `shell/<name>.plm` (not `scene shell/…`) or you leave a duplicate running.
23. **Spotlight is more than an app list** (`spotlight.luau`): every row is an entry `{ name, sub, kind, icon, run }` (kind 0 app, 1 calculator result, 2 web search, 3 command). Sums are evaluated by a small parser (no `loadstring`), `g|ddg|yt|gh|w|maps <text>` search the web through `xdg-open`, `> text` (or a command's name) lists commands, and with no match it offers a web search. New commands go in `COMMANDS`; the scene needs `say:<scene>` for what they drive.
24. **The clock** shows only the time in the centre pill (no date): `clock_text`, painted by `topbar.luau` (and the same in `dashboard`, `lock`) through `shell/clockfmt.luau`. `hour12` (default true: `2:05 PM`; false: `14:05`) is a theme fact: Settings → General → "24-hour clock" flips it, broadcasts it with the theme and saves it in `~/.config/pleamar_shell.json`; `start.sh` restores it.
25. **Settings** (icon glyphs are nudged by `GLYPH_DX` in `settings.luau`: nerd-font glyphs are not symmetric in their box, so measure and offset) (`settings.plm` + `settings.luau`) is a sidebar (with search; `model cats`) and 8 tabs (Wi-Fi, Bluetooth and wallpaper choice live in the Control Center and the wallpaper picker, not here), all backed by real controls: Appearance (light / dark / auto by time of day: `appearance` fact, `set_mode`; the Control Center's tile sends `set_dark_mode`), Displays (niri `msg output` scale / mode), Sound (audio service), Notifications (`banners`, `banner_ms`, DND → notifications scene), Menu Bar & Dock (`pref_*` facts in topbar), Shortcuts (parsed from niri's `binds` blocks; `Super + /` opens it), General, Software Update (`checkupdates`). Preferences are saved in `~/.config/beskar/prefs.json` (look and clock in `~/.config/pleamar_shell.json`) and pushed to the other scenes by `say` at start and on change. Components (`Card`, `ToggleRow`, `SliderRow`, `Seg`, `Chip`, `Btn`, …) keep every tab short: use them for a new option.
26. **The lock screen** (`lock.plm` / `lock.luau`) is `kind: lock` (ext-session-lock): blurred wallpaper, big clock and date, your picture, a password pill (PAM through `auth.check`), a shake and a message on a wrong password, and Sleep / Restart / Shut Down (the last two need a second tap). It has NO bypass. A lock surface's `size` is a box centred on each monitor (paint the backdrop far beyond it) and `screen.width` / `screen.height` are not usable in it; every event the logic receives needs `->` (the old lock never unlocked because `unlock` lacked it). Never test a lock against the live session: run a nested niri (`env -u NIRI_SOCKET niri -c min.kdl`, it prints `wayland-N`) and start the scene with `WAYLAND_DISPLAY=wayland-N`, screenshot it with `WAYLAND_DISPLAY=wayland-N grim`. Recovery if the locker dies: from a text console, `XDG_RUNTIME_DIR=/run/user/$UID WAYLAND_DISPLAY=wayland-1 bin/pleamar --say lock "fact locked false"`. Lock when away: `shell/idle.sh <minutes>` writes `~/.config/beskar/hypridle.conf` (idle and before sleep) and runs hypridle; Settings → General sets it (off by default).
27. **Desktop widgets** (`widgets.plm` + `widgets.luau`, plan in `docs/WIDGETS_PLAN.md`): ONE scene, one `level: bottom` surface per monitor (`level: bottom, top while editing`; NOT background: the wallpaper scene is a background surface too and the one created last is on top, so after any wallpaper restart the widgets vanished behind it), click-through except the cards. `model ws` (id, scr, kind, sz, x, y) is the desktop; a `Card(w)` component per record draws the glass plate and one face chosen by `w.kind` (1 clock, 2 date, 3 weather, 4 battery, 5 system, 6 music, 7 month calendar, 8 day progress, 9 volume + brightness sliders; size 0 small 160x160, 1 medium 336x160, 2 large 336x336). There is NO slot pool: a card exists only while its record does (the model is `max 16`: every `max` copy is compiled in, so keep it small). `widgets.luau` is the only writer of `~/.config/beskar/widgets.json` (cards per output NAME, atomic write, debounced) and learns which copy is on which output from `/tmp/pleamar_widgets.log` (start.sh must log there). Feeds (weather, system) start only while a card of that kind exists. The toolbar of edit mode is its own scene, `widget_bar.plm/.luau` (panel id 10, island `bp`, `open_panel 7`): it grows out of the dock like Spotlight and the wallpaper strip, its buttons only `say widgets "emit …"`, and the bar opening / closing and edit mode start and end together (`w_bar_open`, `edit_done`); kinds and presets live in `widgets_data.luau`, shared by both scenes. Edit mode (`edit_toggle`: Apple menu "Edit Widgets…", Spotlight `Edit Widgets`, `Super+Shift+W` → `start.sh widgets`, Settings → Menu Bar & Dock): dim, drag (`drag_id/dx/dy` facts; with Grid on a card lands on the nearest free cell of the card grid: cells of 160 px with a 16 px gap, origin 48,72, so the gap is always 16; Tidy up packs everything in reading order; toggling Grid only changes how the next drops land, it never moves cards), size button cycles the allowed sizes, ✕ removes, Undo (20 snapshots), add chips and layout presets (in the bar) (Glance, Dashboard, Focus, Listening, Bare). Settings can hide all widgets (`pref_widgets` → `widgets_on`). To add a widget kind: a face component + `group { show: w.kind == N; … }` in `Card`, an entry in `KINDS` (widgets.luau) and its data. Test in a nested niri (rule 26) and mind that `--say widgets-<pid>` must be run with the nested `WAYLAND_DISPLAY`.
28. **The colour engine** (settings.luau, theme.plm): "Colours from the wallpaper" (`accent_auto`) picks the picture's dominant colour with ImageMagick (12 colours, scored by coverage, a little by saturation, ignoring near black or white; matugen's own `--prefer saturation` chose yellow specks on a grey wallpaper) and runs `matugen color hex <that> --json hex --dry-run -m dark -t <scheme>` (style Tonal / Vibrant / Neutral / Soft = `pal_style` 0-3; Soft is Tonal at tones 70 / 60 with 22 % of the colour removed: matugen itself has only the schemes and `--contrast`, no chroma setting), keeps accent (primary tone 60 dark / 50 light), a second colour (tertiary) and the surface, for both modes, in `~/.config/beskar/palette.json`, and sends the ones for the current mode as `pal_*` facts (0..1) to every themed scene (`push_palette`, also after every theme broadcast and again 3 s and 8 s after start). `theme.plm` turns them into `accent_c`, `focus_c` and `bg_color` through `pal_on` (`rgb(...)`); the frame's and widgets' `bar_color` use `surf_c`. The wallpaper picker only sends `text pal_src <path>` to settings. Any new colour that must follow the wallpaper has to use the theme tokens, never a hex value.
29. **The wallpaper is painted by pleamar, not awww** (`wallpaper.plm` + `wallpaper.luau`, started first by `start.sh`, which also stops any leftover `awww-daemon`): one `level: background` surface per monitor with `reserve: -1` (without it the compositor puts the surface below the bar's reserved strip and the top shows grey) draws `~/.config/beskar/wallpaper` with `fit: cover`; the picker (wallpapers.luau) writes that file and says `text wp_new <path>` to the `wallpaper` scene, which loads the new picture as `wp_b` and reveals it over `wp_a` (`wp_fx` 0 circle growing from the top right, 1 fade, 2 wipe), then swaps. If the shell is not running there is no wallpaper (the price of having no daemon). Nothing else in the repo may call `awww`.
30. **Other apps wear the theme** (`shell/appthemes.sh`, `assets/matugen/`): Settings → Appearance → "Theme other apps" (`pref_apps`, on by default, saved in prefs.json). On every theme change (`apply_apps` in settings.luau, debounced, plus 5 s after start) it runs `appthemes.sh setup` (idempotent: one include line per app, each file saved once as `<name>.beskar-bak`; every line contains `beskar/themes` so `remove` can take them out, and NO inline comments: kitty reads them as part of the path) and `appthemes.sh apply dark|light <source #hex> <scheme>`, which renders our own matugen templates (`assets/matugen/config.toml` + `templates/`, matugen `{{colors.<role>.default.hex}}` syntax) into `~/.config/beskar/themes/`: kitty, alacritty, ghostty, foot, `gtk.css` (libadwaita named colours, imported LAST from `~/.config/gtk-3.0|4.0/gtk.css`), and a qt5ct/qt6ct colour scheme; it also sets gsettings `color-scheme` and the adw-gtk3 theme, and reloads kitty (USR1; alacritty live-reloads). The source colour is the wallpaper palette's (`PAL.src`) or the chosen accent. ANSI colours are fixed readable sets with the accent as blue (`@A<n>@` placeholders). Qt apps need `QT_QPA_PLATFORMTHEME=qt6ct` in niri's `environment` (next login). Test with a fake `$HOME` and nested niri, never by hand-editing the user's terminal configs.
31. **Polkit agent** (`polkit.plm` + `polkit.luau`, started by `start.sh`, panel number 8 in `FOCUS_PANELS`): the logic's `sys.watch("polkit")` makes this process the session's authentication agent (one per session: never start a second one, a nested test shell included while the live one runs; test nested BEFORE starting it live, or with `pkexec true`). A modal sheet like the session dialog (`open_screen`, keyboard exclusive): polkit's message, the prompt, a password field (`secret` must be a literal, so it is always hidden), Enter / Authenticate answers (`polkit.answer`), Esc / Cancel gives up (`polkit.cancel`: the program is told "Request dismissed"), `error == "wrong"` shows "Wrong password, try again" and shakes. Every wrong answer counts for pam_faillock like any login: `faillock --user $USER --reset` after tests.
32. **Install, doctor, update, welcome**: `./beskar` (repo root) is the user-facing command: `doctor` (read-only checks with the Arch package line), `install` (clones and builds pleamar if missing, writes `~/.config/niri/beskar.kdl` with spawn-at-startup, struts, the Qt env and the binds, and one `include "beskar.kdl"` line in config.kdl with a `.beskar-bak` backup; it leaves a niri config that already mentions `start.sh` alone), `update` (git pull --ff-only for Beskar and pleamar, rebuild, restart), everything else goes to `shell/start.sh`. First run: `welcome.plm/.luau` (panel number 9) opens itself 7 s after the shell starts when `~/.config/beskar/welcome-done` is missing: three pages (what it is, light / dark / auto + wallpaper colours + theme other apps through `say settings`, shortcuts); `./beskar welcome` shows it again. Test `install` with a throwaway `HOME` containing a valid multi-line KDL config, never against the real one.
33. **Night light, power mode, privacy dots**: Settings tab 8 "Night Light & Power". Night light is `shell/nightlight.sh off|on K|auto K` (wlsunset: niri supports wlr-gamma-control; "on" is a constant K through `-t K -T K+1 -S 23:59 -s 00:00`, "auto" uses `~/.config/beskar/location` for sunrise/sunset, else 06:30 to 18:30); the choice is `night` / `night_t` in prefs.json and `start.sh` restores it at login. Power mode is `powerprofilesctl get|set power-saver|balanced|performance` (power-profiles-daemon; the card says so when it is missing). Privacy dots are in the bar's right row (`priv_cam` green, `priv_mic` orange), polled every 4 s by `topbar.luau`: camera = some process has a `/dev/video*` open (`fuser`), microphone = `pactl list short source-outputs` is not empty. Not done: game mode.
34. **Panel content goes through ONE wrapper, `PanelBody(x, y, up) { … }`** (`shell/common/morph_core.plm`): it shows the content only on the monitor that has the panel, clips it to the glass as the glass grows (`mp_rh` from the top island down; `mp_bh` from the dock up when `up` is 1, with `y` = the surface height) and fades it in late (`mp_fade`). Every panel that grows out of the bar or dock (Control Center, notifications, dashboard, music, Spotlight, clipboard, wallpapers, widget bar) uses it; a new panel must too, never its own `group { show: mp_here … }`, or its icons appear before the glass has grown.
35. **Window overview and live previews** (`overview.plm` + `overview.luau`, `appswitcher.plm` + `appswitcher.luau`, `topbar.plm` + `topbar.luau`): Modal HUDs (app switcher, overview) use ONE NAMED surface with `screens: each` and `open: (open or seen > 0.02) and open_screen == screen.index`, `keyboard: exclusive while open` (rule 15). Windows are queried via `niri msg -j windows` and mapped by title/app to pleamar's `thumbnails` service (`sys.watch("thumbnails")`). Window thumbnails are requested only for visible windows (`thumbnails.want` for switcher and dock hover; `thumbnails.live` for the overview grid) and released (`thumbnails.want()` / `thumbnails.live()` with no args) when closed to avoid wasted copies. Where the compositor lists windows but does not yet export `ext-image-copy-capture` frames (`capturing` false / empty picture), cards render a centered app icon inside the preview viewport while preserving the preview card geometry, app badge, title, workspace tags, and selection state.
36. **Live activities in the centre pill** (ALL of them are now the same CARD as the volume / brightness / microphone feedback: `card_open(id, ms, {glyph, title, sub, value, tone, thumb})` in `topbar.luau` fills `card_*` and `osd_kind = 3`; a click on it is `card_click`; the old small `act_*` rows are gone) (`topbar.plm`, `topbar.luau`, `capture.luau`, `spotlight.luau`): The centre pill (Island) arbitrates live activities and ambient indicators in strict priority order: banner (`kind = 1`, id 7) > volume/brightness (`kind = 2`, id 8) > timer done (id 11, 5 s) > charging (id 12, 3 s: bolt glyph, 'Charging' / 'On battery' and percent, suppressed at startup) > screenshot taken (id 13, 3 s: 'Screenshot saved' + thumbnail, click opens with xdg-open) > privacy alert (id 14, 2.5 s: 'Camera in use' green / 'Microphone in use' orange when either device activates before settling to the right-row privacy dot) > ambient (timer countdown ring + mm:ss with click-to-cancel, recording dot + time, music cover + wave bars) > clock. Takeover activities temporarily replace the clock in `center_row`, allowing the width spring (`follow cw = center_row.width + pad * 2`) to smoothly morph the pill geometry with zero popping.
37. **Click outside closes a panel.** The frame (`topbar.plm`) has a full-screen `outside_zone`, declared before every button zone, active while a panel owns an island (`rp_on`, `cp_on` with `cp_kind == 0`, `bp_on` unless `bp_keep`, which is set for the widget bar because you work on the desktop while it is up). A press emits `outside_click`; `topbar.luau` then says `fact open false` to every panel scene. The panels are separate overlay surfaces, so clicks inside them never reach this zone.
38. **Top bar styles (Notch, Strip)**: The top bar style is controlled by `fact bar_style` (0 Notch, 1 Strip), saved in `~/.config/beskar/prefs.json` as `"bar_style": N` and configured in Settings → Menu Bar & Dock via a `Seg` control. Topbar logic loads `bar_style` at startup and settings pushes it via `say("topbar", "fact bar_style N")`. The frame (`topbar.plm`) morphs fluidly between styles using `prop s_strip ~calm`: Style 0 (Notch, default) draws the three separate islands with curved fillets; Style 1 (Strip) renders a full-width flat bar (`strip_bar`) spanning the entire top edge with flat bottom edge (height 38 px, corners and fillets flattened to 0). In both styles, panel glass (`power_m`, `center_m`, `right_m`) still seamlessly grows out of the bar as one piece of glass with rounded corners during panel reveal, and banner/live activities in the center pill remain fully functional.
40. **The capture picker** (`capture.plm` + `capture.luau`, panel number 11, `start.sh capture`, Print / Super+Shift+5): a full-screen named surface per monitor (rule 15) over a FROZEN picture of the focused monitor (`grim` to `/tmp/beskar-cap-*.png`, shown through `text shot_path`). Region = drag, move by the inside, four corner handles, Enter / the Capture button; Window = niri's `screenshot-window` of the focused window (niri gives no window rectangles); Screen = the frozen picture itself. Photo crops the frozen file with `magick` (scaled by picture width / `scr_w`), saves to ~/Pictures/Screenshots and `wl-copy`s it; Video runs `wf-recorder` (`-g` with the monitor's logical offset for a region, `-o` for the screen). A rule can `emit` an event with at most ONE argument: put several values in facts first (`scr_w = …; emit do_region`).
41. **Icons are centred by ONE font and ONE component** (`shell/common/icons.plm`, `include` it after theme.plm): the default font draws Nerd Font glyphs off-centre by up to 11 px, each differently; `JetBrainsMono Nerd Font Mono` centres every one (measured). Draw glyphs with `Sym(g, x, y, size, color)` or `SymTile(g, x, y, side, corner, color)`; a glyph that changes with a fact, or sits in a model, is a `text` with `family: "JetBrainsMono Nerd Font Mono"`. Never a bare glyph `text` (no more per-icon nudging like the old `GLYPH_DX`).
42. **Shared UI parts live in `shell/common/ui.plm`** (include after theme.plm and icons.plm; each component's signature is in the file's header comment): Plate, Switch, ToggleRow, Btn, Pill (tones), Seg, Chip, Slider, RowFrame (selected-row look), EmptyState, PanelHeader, PanelSearch, SectionLabel, KeyHint, Divider, ScrollBar, SelectCard (switcher / overview tiles), CardBg (every card fill). Use them instead of drawing a toggle, button, chip, slider, row highlight, empty state or header by hand; a control that two scenes need goes there. **Tokens (theme.plm): never a hex value or a bare number in a scene** for these: `on_accent` (text on an accent fill; was #ffffff), `scrim_c`, `btn_fill`, `switch_off`, `field_bg`, `sel_bg`, `bar_color`; radii `r_s` 8 · `r_m` 12 · `r_l` 16 · `r_xl` 24; text sizes `t_title` 15 · `t_body` 13 · `t_sub` 12 · `t_cap` 11.5 · `t_micro` 10.5 (headline sizes 17+ stay literal). Hover = a spring `glow`/`on` that adds 8-22 % of the accent or `item_bg`; selection = `RowFrame`. Every modal / dock panel closes the same way: Esc, a click outside, or losing focus (`on blur`), except the widget bar (you work on the desktop with it); list panels move with Up / Down (Tab = Down), pickers with Left / Right; a dock panel that has a search (Spotlight, clipboard) has it at the bottom; the wallpaper strip has none on purpose.
43. **Anything longer than its room scrolls, with a bar.** A pane taller than its window is a layout with `view: w, h` (and `step:`) named so its `.scroll` / `.content` can feed `ScrollBar` (Settings: each tab's column `tcol_N`, `view: 560, 500`). A layout declared inside a component's `children` cannot have its `scroll` set from a scene-level rule; when keys must move a list (Spotlight: 24 results kept, 7 seen), scroll it yourself: a `fact` target + `prop` spring + `column { at: x, y - sc }` inside a `clip box`, a `zone` for `on scroll`, and `ScrollBar(sc, rows * h, seen)`.
44. **One design language for the dock panels** (Spotlight, clipboard, wallpapers, and any new one that grows out of the dock): a HEADER at the top (`PanelHeader(glyph, title)` in `common/ui.plm`; the scene adds its count and actions on the same line at y 30, as `Pill(..., 26, true)`), the content in the middle, and the SEARCH FIELD always at the BOTTOM, nearest the dock: `PanelSearch(w, ph)` draws the divider and magnifier, and the scene's own `input q { at: 68, ph - 50; width: w - 110; size: 19 }` sits on it. Never a search field at the top of a dock panel.
45. **Weather** (`weather.plm` + `weather.luau`, panel id 15, island `cp`, opened by a click on the weather in the clock pill: `open_weather`): Open-Meteo forecast (current, details, next 8 hours, next 5 days; no key) for the place in `~/.config/beskar/location` (`LAT LON City`; `location.luau` reads it on every call, no cache). A second view picks the place: "Use my location" (ipwho.is) or a city search (Open-Meteo geocoding, 450 ms debounce); choosing writes the file and says `weather_reload` to the top bar, dashboard and widgets, which read it again. The surface is `keyboard: on_demand` (a click on the search field takes the keys). Codes → glyphs / words live in `weathercodes.luau`.
46. **Dashboard ("Today")** (`dashboard.plm/.luau`, opened by the clock): a time-of-day greeting with the user's name, the weather card (a click opens the weather panel), a Monday-first month calendar (`cal_shift`, prev / next / click the title for this month; `cells` model of 28-42 days), CPU / memory / disk with uptime, and the battery's REAL state (power supply + `upower` time: Charging / Plugged in (charge limit) / Fully charged / On battery). No UTC clock and no fake events. A scene's `run` only allows what its `permissions` list: `date` is not `sh`, and a refused command throws and stops the rest of the file.
47. **Never start the shell from an agent / terminal session directly.** Anything a tool call starts (even with `setsid`) lives in that session's cgroup (`t3code-claude-*.scope`) and is SIGKILLed when T3 ends or restarts the session: that is why the whole shell "stopped randomly" (no pleamar process, no supervisor). Start it in its own unit: `systemd-run --user --unit=beskar-shell --remain-after-exit --collect shell/start.sh restart` (check with `cat /proc/<pid>/cgroup`: it must say `beskar-shell.service`). Restarting a single scene by killing its pid is fine: the supervisor, in the unit, starts it again.
39. **Scenes are supervised.** `start.sh` runs every scene through `shell/supervise.sh <scene> <log>`, which starts pleamar again (after 1 s; 30 s if it dies 5 times within 20 s each) when it exits or crashes and notes it in the log. To restart one scene by hand just kill its pleamar pid and the supervisor brings it back; `start.sh stop|restart` kills the supervisors first.
48. **Updates** (`updates.plm` + `updates.luau`, panel id 16, island `rp` like the Control Center; Settings has no update tab): the scene runs `checkupdates` (+ `<helper> -Qua` for the AUR; helper = `paru`, else `yay`, by `command -v`) 3 s after start, every 30 min, on "Check" and when opened if the last check is older than 5 min, keeps the list, and tells the top bar the count (`say topbar "fact upd_n N"`). The bar's right row shows a download arrow with the count (`UpdateIcon`, left of Wi-Fi) only while it is above 0; a click (`open_updates`) opens the panel: the packages (scrolls, 60 at most, AUR ones with an orange icon) and "Update all", which opens ONE terminal (`$TERMINAL`, else kitty, foot, alacritty, ghostty…) running `<helper> -Syu` (or `sudo pacman -Syu`) with a single sudo password, like iNiR does; the list is checked again when the terminal closes. Do NOT go back to pkexec / the polkit popup for this: pkexec asks again for every command (one prompt per package). `polkit.luau` still calls `require("exclusive")("polkit")` so other panels close when the popup opens. A new panel needs `say:updates` in the scenes that use `exclusive`.
50. **Weather, music, today (dashboard) and updates are ONE scene, `panels`** (`panels.plm` + `panels.luau`; the old weather / music / dashboard / updates scenes and their `say:` names are gone). Why: every scene is its own process (~22 MB PSS and 17 threads even when idle; merging four saved ~70 MB): pleamar allows several NAMED surfaces in one scene that share facts. The morph state is ONE set (`open`, `open_screen`, `cur` = the open panel's id 3 / 9 / 15 / 16, `panel_h`), because only one panel is ever open; each surface (`weather`, `music`, `today`, `updates`) is open only when `open and cur == its id` on the monitor `open_screen`, and draws its content in `TopBody(x, y, width)` (the named-surface twin of `PanelBody`). Names that two panels could share are prefixed (`wx_*` weather, `dw_*` today's weather card, `d_*`, `up_*` updates). `panels.luau` is the core (reports `panel_open / panel_close / panel_height` to the frame for the id shown, runs each part's `opened(fn)` hook) plus the four parts, each in `module(name, function(panel, opened, shown) … end)` (own locals, `panel.height(h)`). To open one: `topbar.luau`'s `open_island_panel(name)` says `panels "fact open_screen S"`, `"fact cur ID"`, `"fact open true"` (`panel_say`, `MERGED`); closing says `panels "fact open false"`. `exclusive.luau` and the theme broadcast know `panels` (not the four old names); scenes that use `exclusive` need `say:panels`. `weather_reload` reaches both the weather part and today's card (same scene). The same technique can merge more scenes (dock panels, modal dialogs).
51. **The welcome is the only centred dialog (`dialogs.plm` + `dialogs.luau`, `cur` 3, on `modalcore.luau`)**; the SESSION dialog (panel id 11) and the POLKIT password dialog (id 12) are panels of the `dock` scene (rule 52): they grow out of the dock island like Spotlight (frame-drawn glass: `session` / `polkit` entries in topbar.luau's `PANELS`, `DOCK` ids, content in `PanelBody`) and are keyboard-first: session = Enter presses the highlighted button (the action by default, `ses_sel` 1), Left / Right / Tab choose, `y` confirms, `n` / Esc cancel, with a 60 s countdown; polkit = the password field has the focus, Enter authenticates, Esc cancels, a click outside does not close it (`panel.keep()`), and closing it any other way tells the program it was dismissed. Set the session kind with `say dock "fact kind N"` (0 shut down, 1 restart, 2 log out) then `open_panel 5` (or `emit show_panel 11`). The polkit agent lives in the dock process (`sys.watch("polkit")`): never start a second one.
52. **Spotlight, clipboard history, wallpaper strip and widget bar are ONE scene, `dock`** (`dock.plm` + `dock.luau`; the four old scenes are gone). Same technique as rules 50 / 51: four named surfaces that grow out of the dock, one shared `open` / `open_screen` / `panel_h` (morph_core.plm) and `cur` = the panel id (4 spotlight, 5 wallpapers, 6 clipboard, 10 widget bar, 11 session dialog, 12 polkit dialog). `panelcore.luau` is the shared core of every merged panel scene (`panels`, `dock`): `local module = require("panelcore")({ name = id })`, then `module(name, function(panel, opened, shown, closed) … end)` per part (`panel.height(h)`, `panel.keep()` = survives a click outside). It reports `panel_open / panel_close / panel_height` to the frame and handles `toggle_dock(id)`, `show_panel(id)`, `close_panel(id)` and `outside_close`. Key rules are guarded (`on key Down while cur == 4 { … }`), and `on blur while cur == N and not fresh`: switching straight from one panel to another sends a `blur` to the new one, so `panelcore` sets `fact.fresh` for 500 ms after a panel takes over. Facts that two panels could share are prefixed (`sp_sel` spotlight, `clip_sel` clipboard). Open one: `topbar.luau` (`DOCK`) says `dock "fact open_screen S"` then `emit toggle_dock ID`; the widgets scene closes the bar with `say dock "emit close_panel 10"` and sets `snap_on` / `can_undo` on `dock`. `exclusive.luau` also listens to `panel_sync` / `dlg_sync` (a logic that sets `fact.open` itself does not trigger `on("fact:open")`). New dock panel: add a surface, a key-rule guard and a `module(...)` part; set `cur` to its panel id.
53. **App switcher, window overview and capture picker are ONE scene, `modals`** (`modals.plm` + `modals.luau`; the old appswitcher / overview / capture scenes are gone). Same technique as rules 50-52: three named surfaces (`switcher`, `overview`, `picker`) share `open`, `open_screen`, `cur` (1 switcher, 2 overview, 3 capture) and the `modal` layer (`seen`, `scale`). `modalcore.luau` (also used by `dialogs`) gives each part `opened(fn)`, `closed(fn)`, `shown()` and sets `fact.fresh` for 500 ms when a window takes over (so `on blur while cur == N and not fresh` ignores the blur the previous window sends). The apps and thumbnails services are watched ONCE (`shared_watch` in modals.luau) and handed to every part: never call `sys.watch` for the same service twice in one scene. IMPORTANT: inside a named surface of a scene with several surfaces, `screen.width` / `screen.height` do NOT measure that surface (they came out as the first surface's size: the capture picker's zones were 1160x220); use the surface's own `picker.width` / `picker.height`. Open: `topbar.luau` (`MODALS`) says `modals "fact open_screen S"` then `emit toggle_dialog ID` (capture: `emit cap_toggle`, which grabs the frozen picture first); `say modals "fact mode N"` / `"fact kind N"` preset the picker; `start.sh shot` says `modals "emit shot_now"`; the top bar's recording dot says `modals "emit toggle_record"`. Names that two windows share are prefixed (`sw_*` switcher, `ov_*` overview).
54. **Never leave a `wave`, `spin` or `blink` running in a scene that is always up.** They keep the whole scene painting at the monitor's rate for ever, even when nothing they draw is visible: the top bar's music bars and recording dot (`wave`) made it paint ~100 frames a second all day (`pleamar --report topbar`: "animating 100%", ~5 % of a core; now 0 %). The bars now use `let mb1 = sin(m_ph * 5.3)` with `m_ph` (degrees) advanced by `topbar.luau` every 50 ms ONLY while music plays or a recording runs (`wave_kick`). Measure with `./bin/pleamar --report <scene> --seconds 10`: an idle scene should say "barely animated".
18. **Names.** Component-scoped names are mangled (`hit#Shell7#DockItem36`); `--say` can see them via `describe`.

## Working style

- Reuse before writing: the reference repos in `references/` (inir, minflair, capsule, pleamar, …) show
  island geometry, morphing and tray handling worth adapting, but port the *idea* into `.plm`, not their code.
- Verify visually: restart the scene, `grim` both monitors, look at the result. `--check` passing does not mean it looks right.
- Do not commit unless asked.
